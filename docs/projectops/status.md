- Phase 2 pagination: GET /projectops/clients and /projectops/project-requests return keyset-paginated `{ items, nextCursor }` pages (limit 1-100, default 50; tamper-checked cursors bound to their list). Migration 0008 adds the two matching indexes. The client directory loads more on demand. Measured with 20,000 clients: 208 ms / 4 MB per request before, 7 ms / 10 KB after. Tests that hardcoded the latest migration (version list or count) now derive it from the migration list.
- Phase 2 API response contract: PostgreSQL-backed responses no longer pass raw columns through. Measured over all 21 read endpoints with every entity type: 225 duplicate snake_case keys removed (652 keys to 397), and every remaining value identical to the previous responses (old and new servers compared on the same database). A route wrapper also misread notes as prepared HTTP responses (they have `status` and `body` fields) and wrote `headers` into their JSON; it now uses the serializer's own check. `contract-postgres.test.ts` enforces camelCase-only responses and field parity between the PostgreSQL and memory executors.
- Known inconsistencies found by the contract comparison, not yet changed: empty optional single-word fields are `null` on PostgreSQL but omitted in memory; some terminal actions take the actor from the session (`decidedBy`) while others still require it in the request (`archivedBy`, `completedBy`).
- Phase 2 error logging: server errors were logged as a warning with only a status and code, so a 500 could not be diagnosed, and a database outage answered product requests with 500. Server errors are now logged at error level with method, path (no query string) and the error itself: name, message, code, stack, bounded cause chain and PostgreSQL constraint/table/column, without pg `detail`/`where` or parameters and with connection-string credentials redacted. Database-unreachable errors (shapes recorded from pg 8.23 against PostgreSQL 16) return 503 `SERVICE_UNAVAILABLE` with `Retry-After`; real-use run with PostgreSQL stopped: product read 500 before, 503 after, recovery without restart unchanged. Idle pool errors are logged structurally as `db.pool.error`. `outage-postgres.test.ts` cuts the database off through a TCP relay and proves the 503s, the log records and recovery.
- Phase 3 deployment (Render, owner-approved 2026-10-14): `render.yaml` updated to Render's current plan ids (`0.5c-512mb` service, `0.1c-256mb` database), Frankfurt, a 1 GB disk instead of the tier's billed 15 GB default, a private-only database (`ipAllowList: []`) and deploys gated on GitHub checks (`checksPass`). `GET /health/live` reports the running commit, so the deployed smoke verifies it instead of relying on a manual attestation; a hand-started GitHub Actions workflow runs the smoke with repository secrets.
